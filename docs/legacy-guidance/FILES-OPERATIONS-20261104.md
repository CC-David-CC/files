# Files window document-operation integration

Files uses the host's session-scoped `documentOperations`, including subtree claims from `63271e457`. A local action reserves before its picker or confirmation, claims selected source files/folders before prompting, and claims destinations before mutation; folder actions use subtree claims. Account paths use `mirror:` and temporary Linux paths `guest:`. Upload picker ownership ends on native cancel/change, and external drop reserves before processing. Chonky is inert and Files controls are disabled for its own active operation; handlers and agent open/word-count check admission independently. Explicit sync is not a background-synchronization lock on other documents. Directory reload following a completed action is scheduled without retaining its claim.

There is a remaining UI limitation: Files has no one document identity, and the current controller does not expose a read-only aggregate of exact/tree availability for a multi-selection. Consequently a toolbar action for a peer-busy selection can appear available, but rejects before its prompt or mutation once invoked. A shared bounded selection availability API would be needed for proactive disabled state; this patch does not invent a second coordinator. Cross-tab/device writers remain governed by the storage protocol, not these session-local claims. Multi-file moves/deletions/uploads are not atomic. On disposal, a previously dispatched non-cooperative mutation may complete after the claim is released; iteration checks prevent dispatching subsequent moves/deletions or guest extraction entries. Existing version/CAS checks and their limits still apply.

The actual `mountApp`, Files/Chonky view, Text and CodeMirror were run in isolated Chromium at 1366x900 and 390x844. Held in-memory storage tests covered same-file Text save versus Files download and agent open, Files download versus Text Save, error/close and `readBlob` abort signal, no late object URL, held rename confirmation/cancel, upload picker cancellation with a test stub replacing the native dialog, parent-tree/child-file exclusion both directions, and disposal after one non-cooperative deletion with no subsequent deletion dispatched. The file service, prompts and picker were test doubles; this is not a signed-account, physical phone or actual OPFS Worker test. The separate earlier real-OPFS copy cancellation evidence remains independent. Not every Files action or third-party shortcut was executed in this fixture.
